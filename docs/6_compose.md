# 6_compose — 이슈 하나를 소재 후보 하나로

**정본은 `prompts/6_compose/v1/system.md` · `user.md` 다.**

- 어느 버전을 쓰는가 → `tuning.yaml` 의 `prompt_versions.compose`
- 배치 전체 설계 → `docs/5_cluster.md`
- 결정 이력 → `db/DECISIONS.md`

## 6·7·8단계를 한 콜로 합쳤다

```
6  소재 생성      title · summary · keywords
7  선별           **임계 미적용**
8  topics 조립    rank · sources[] · _hot 병기
```

선별 임계를 안 건 이유는 **임계를 정하려면 탈락선 아래까지 봐야 하기
때문**이다(#36). 지금은 전 이슈를 소재화하고 눈으로 본다 —
캘리브레이션 모드이고, 종료 조건은 `TUNING.md` 에 있다.

그래서 지금은 **이슈 ≡ topics 1행**이고, `issues` 테이블이 없어도 잃는 게
없다. 임계를 켜는 순간 탈락 이슈가 저장 자리를 잃고, **그때가 `issues` 가
되살아나는 시점이다**(#50).

## User Prompt 에서 기사 수·매체 수를 뺐다 (2026-08-26)

스파이크 프롬프트에는 이 줄이 있었다.

```
기사 수: {{ $json.n_articles }} · 매체 수: {{ $json.n_press }}
```

**그런데 System Prompt 가 정확히 그 둘을 쓰지 말라고 한다.**

```
기사 수, 매체 수, 최신성, 화제성, 예상 검색량은 이 점수에 반영하지 마라.
그 값들은 다른 단계가 따로 판단한다.          — business_relevance 절

기사 수·매체 수·화제성·검색량은 근거로 쓰지 마라.  — rationale 절
```

**쓰지 말라면서 입력으로 줬다.** 결정 #37 이 `business_relevance` 를 순수
서비스 직접성 축으로 좁힌 이유가 "화제성은 코드가 세고 검색량은 NULL 인데
모델이 추정하면 축이 침범된다"였는데, 그 값을 라벨까지 붙여 눈앞에 놓는 건
그 결정과 어긋난다.

두 축을 분리하기로 했다.

```
business_relevance  =  서비스 직접성
hot_*               =  열도
```

`article_ids` 배열 길이로 기사 수가 어차피 유추되지만, 그건 **구조적으로
필요한 입력에서 부수적으로 드러나는 정보**이고 `기사 수: 3 · 매체 수: 2`
라는 라벨로 **평가 축처럼 제시하는 것과는 다르다.**

빼두면 첫 실행에서 **혼입 요인이 하나 줄어** 점수 분포 해석이 깨끗해진다 —
스파이크에서 하한이 0.42 로 떠 있던 것이 합본 편향 때문인지 판단할 때.

## 첫 실행 결과 (2026-08-26 · 51건)

```
business_relevance   0.34 ~ 0.95 · 평균 0.701 · 중앙값 0.72
  0.80~1.00   21건
  0.50~0.79   17건
  0.20~0.49   13건
  0.00~0.19    0건
```

**스파이크(33건)와 비교하면 하위권이 두꺼워졌다.**

```
             하한    0.20~0.49
스파이크      0.42       4건
이번         0.34      13건
```

바닥이 깔리기 시작했다. **다만 이슈 구성 자체가 달라서 기사 수·매체 수를
뺀 효과라고 단정하면 안 된다.** 캘리브레이션 종료 조건은 배치 3회고
이번이 1회다.

상위와 하위가 뜻대로 갈린다.

```
0.95  CBAM 검증 요건·인프라       0.34  중국 COP33 유치
0.94  KSSB 재무연계              0.38  영국 넷제로 비용 논쟁
0.93  탄소 산정 경계·데이터 기준   0.38  ESG 등급 하락의 주가 충격
0.92  공급망 실사 데이터·검증      0.42  북극 석유·가스 개발
```

### 축 침범이 없다

```
search_demand   NULL 아닌 것 0건    ← 모델이 검색량을 지어내지 않았다
keywords        4~5개 · 빈 것 0건    ← 프롬프트 지시(3~6) 준수
```

**`search_demand` 가 전부 NULL 인 게 중요하다.** 하나라도 값이 있으면
모델이 없는 공급원을 추정한 것이고 축이 침범된 것이다.

### 제목 가운뎃점 3건 — 전부 결합어다

```
CCS·CDR 프로젝트는 기술보다 실행 단계에서 무엇을 준비해야 할까
노르웨이는 왜 북극 석유·가스 생산을 2035년까지 이어가려 할까
지속가능·전환금융 자금이 몰릴 때 기업은 무엇을 준비해야 할까
```

프롬프트가 막으려던 건 `CCUS 투자·경제성·인허가 동향` 같은 **키워드
나열형**이고, 위 셋은 `CCS·CDR`·`석유·가스`처럼 자연스러운 결합어다.
**`·` 존재 여부로 검사하면 셋 다 잡히지만 품질 문제는 아니다** — 경고기가
넓게 잡는 것뿐이라 지금은 검사를 넣지 않는다.

### 합본 편향은 관측되지 않았다

소재 작성과 점수를 한 콜에 합친 것(#36)이 점수를 밀어올린다고 의심했는데,
**고득점 몰림이 더 심해지지 않았고 낮은 점수대가 충분히 나왔다.** 점수를
별도 콜로 분리할 근거는 아직 없다.
